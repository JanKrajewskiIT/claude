# i18n & Built-in Copy

## Ownership

- VelvetUi owns generic reusable copy (button labels, empty states, validation fallbacks, aria descriptions)
- No hardcoded user-facing strings in component logic; add to `src/i18n/messages.ts`
- Don't reflexively expose every label as a required prop; the library owns sensible defaults

## Text resolution order

1. Semantic prop override — when customization is genuine public API (e.g. `label`, `message`)
2. `messages` override — for consumer-level localization
3. Built-in `useI18n()` default — library fallback for generic copy

## Adding new copy

- Add the key to `src/i18n/messages.ts`
- Consume via `useI18n()` in the component
- Expose as a prop only when customization is a real consumer requirement
- New generic built-in copy lives in `src/i18n/messages.ts`, never inline

## What belongs here vs props

- Generic labels ("Close", "Loading...", "No results", validation fallbacks) → `messages.ts`
- Domain/semantic text varying per usage → explicit `label`/`message` prop
- Don't push generic copy to props expecting consumers to always override
